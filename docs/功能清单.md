#### ★ 引导类 `IndraBootstrap`（v1.4.0 新增）

**背景**：我们为绕开「TabooLib 内置 ASM 9.7 不支持 class major 69」禁用了官方后处理任务，
但那次后处理**还顺带把 `ProjectInfoKt` 里的 `groupId` 常量从 `"taboolib"` 改写成 `com.indra`**。
禁用后常量没被改写，运行期 `getGroupId()` 返回 `"taboolib"`，
导致 `ClassVisitorHandler` 把所有 `com.indra.*` 判为「非本项目类」丢弃 →
`Plugin.setInstance()` 从不调用 → `pluginInstance == null` →
`BukkitPlugin.onEnable()` 整段静默跳过。

**症状**：插件加载成功、**零报错**，但 `@Awake` 不触发、`@Config` 不生成配置、命令不注册。
（用户观察到的「只生成了 `datasource.yml` 和 `kether.yml`」正是这个指纹 ——
这两个文件分别是**代码直调**与**模块自带资源**，都不走注解管线。）

**修复**：新增 Java 引导类，用静态块抢在 TabooLib 类加载前注入系统属性：

```java
public class IndraBootstrap extends BukkitPlugin {
    static { System.setProperty("taboolib.group", "com.indra"); }
}
```

| 项 | 内容 |
|---|---|
| 文件 | `src/main/java/com/indra/rpg/IndraBootstrap.java` |
| 为什么用 Java | JVM 保证 `<clinit>` 在任何 TabooLib 类加载前执行；不能用 Kotlin `object`（其初始化本身依赖 TabooLib） |
| 构建期保护 | `indraMainTask` 加三条 `check` 断言，引导类缺失或注入语句被删 → **构建直接 fail** |
| 仿真证据 | `tools/sim/Sim.java`：修复前 `0/9` 通过，修复后 `9/9` 通过 |
| 长期方案 | 等上游 Gradle 插件内置 ASM 升到 9.9+，可删 `indraMainTask` 切回官方后处理，引导类一并移除 |

### ⚠️ 关键澄清：26.3 ≠ 1.21.x

Mojang 自 2026 年起把版本号从 `1.x` 改为「**年份.序号**」：

```
1.21.5 (Spring to Life)  →  26.1  →  26.2 (Chaos Cubed)  →  26.3 (Wilderness Bound)
                                    ↑ 不存在 1.22
```

**这带来三个直接影响：**

1. **JDK 必须 17 → 25** —— Paper 26.1+ 起要求 Java 25，构建机的 JDK 也要换
2. **TabooLib 必须 6.3+** —— 26.1 起 Mojang 不再混淆 Minecraft，Spigot Mapping 消失；用 Spigot 译名的代码在 26.1+ **无法运行**（TabooLib 官方迁移文档明确说明）
3. **Paper 26.3 仍是 ALPHA** —— API 可能随构建变动，需评估是否先基于 26.2（stable）开发

### A1 · Vault 经济系统对接

**状态**：✅ **底层已完成**（2026-09-19 随 A2 一并落地），业务层结算待 A3 接入。

**说明**：软依赖 Vault，读取 `Economy` 服务做余额查询与增减，为出售系统与后续商城提供统一货币口径。

| 项 | 内容 |
|---|---|
| 实现文件 | **`common/economy/VaultBridge.kt`**（最终落位，非上表的 `core/economy/`） |
| 关键 API | `Class.forName("net.milkbowl.vault.economy.Economy")` + 反射调 `depositPlayer` / `withdrawPlayer` / `has` / `getBalance` / `format` |
| 依赖方式 | **纯反射，编译期零依赖**。未装 Vault 时 `isAvailable()` 返回 false，调用方自行降级到 `indra_player.coins` |
| 注意 | Vault 本身只提供接口，需服务端装有经济实现（EssentialsX / CMI / 自研） |

> **为什么不用 `compileOnly("com.github.MilkBowl:VaultAPI")`**
> 1. 该坐标只在 JitPack，需认证且部分网络不可达；
> 2. Indra 的后处理（indraMainTask）**不提供 relocate 能力**，把 Vault 类编进产物有包冲突风险；
> 3. 反射在「服务器没装 Vault」时优雅降级，不会 `NoClassDefFoundError`。

**子功能**
- `balance(player): Double?` 查询余额
- `depositResult(player, amount): TransactionResult` 入账（含错误信息）
- `withdrawResult(player, amount): TransactionResult` 扣款
- `has(player, amount): Boolean` 余额校验
- `format(amount): String` 用经济插件自己的格式渲染（带货币符号）
- `isAvailable(): Boolean` 可用性探测

### A3 · 出售系统

**状态**：✅ **已完成**（2026-09-20，v1.5.0）

**说明**：玩家把物品卖给服务器换取货币，单价由配置表驱动，支持图形化界面、单个/批量出售、一键放入、自动出售。

#### 实现方式：按 Phoenix 配置契约重写（不是移植）

Phoenix 的出售**不是自研的**，本质是「把第三方插件 **VitaSell** 的引擎类融合进 Phoenix 的 jar」，
而**引擎源码不在交付物内**：

| 组成 | 归属 | Indra 的处理 |
|---|---|---|
| `VitaSell` / `VitaSellSettings` 引擎本体 | 第三方，已 ASM 重定位 | ❌ 源码缺失 → **完全自研替代** |
| `SellBridge`（88 行转发） | Phoenix 自研胶水 | 逻辑已内化到 `SellEngine` + `SellCommands` |
| `SellTradeLog`（67 行，写文件） | Phoenix 自研 | ✅ 思路移植，**存储方式改为落库** |
| `SellModuleConfig` / `SellCommands` | Phoenix 自研 | ✅ 思路移植 |

**核心策略：保留 `sell/` + `table/` 的配置契约**，用户现有规则/界面文件可**直接拷入使用**。

| 维度 | Phoenix（VitaSell） | Indra |
|---|---|---|
| 规则/界面文件格式 | `sell/` + `table/` 的 yml 结构 | ✅ **完全一致** |
| Money 符号语义 | **负数 = 给予玩家** | ✅ **保留**（否则迁移后反向扣钱） |
| 交易审计 | 写文本文件 `data/sell/trades.log` | ⚠️ **改为落库** `indra_sell_log`（项目硬性约束） |

#### 子功能

- `/indra sell [界面]` 打开出售界面
- `/indra sell open <玩家> [界面]` 为他人打开
- `/indra sell list` 列出界面与规则数
- `/indra sell reload` 热重载规则与界面

#### ★ 防丢物设计（相对 VitaSell 的加固）

VitaSell 是「先扣物再给钱」，Vault 入账失败时物品已消失。
Indra 改为**三阶段**：

```
1. 扫描 → 匹配规则 → 检查条件 → 累加收益（此时不动物品）
2. 尝试 Vault 入账
     ├─ 失败 → 物品原样保留，返回错误，玩家可重试
     └─ 成功 → 进入下一阶段
3. 清空已售槽位 + 执行回调 + 落审计
```

另外：

| 场景 | 行为 |
|---|---|
| 未匹配任何规则的物品 | **留在界面里**，计入「未售出」统计并提示，不静默丢弃 |
| 关闭界面 | 界面内剩余物品**全部还给玩家**；背包满了掉在脚下 |
| Kether 条件求值失败 | 保守判定为「不可售」（**宁可卖不掉，也不让带条件的规则被无条件触发**，防刷钱） |
| 点击装饰图标 | 只拦截，不产出任何动作 |
| 玩家背包区 Shift 点击 | 只搬进「玩家物品槽」，不进按钮位 |

#### 已知待办

- **`Action.Point` 点券字段已解析但暂未发放** —— Indra 没有点券系统，当前只入库统计。需确认对接哪个插件（见「待你确认的问题」#4）。
- `ItemMatcher` 不支持 `nbt:` / `tag:` / `itemmodel:` 及各类插件物品（如 ItemsAdder），需复杂判断请用 `Condition` 的 Kether 脚本。

### A4 · 信标系统（Display 实体 + 物品模型，完全模仿原版）

**说明**：不依赖原版信标方块，用 `ItemDisplay` / `BlockDisplay` 实体配合物品模型「拼出」信标外观，**外观与行为完全模仿原版信标**，并扩展自定义颜色与转动速度。

| 项 | 内容 |
|---|---|
| 实现文件 | `module/beacon/BeaconModule.kt`、`module/beacon/BeaconDisplay.kt`、`module/beacon/BeaconEffect.kt`、`config/beacon.yml` |
| 关键技术 | `ItemDisplay`（物品模型外观）、`BlockDisplay`（底座/光柱）、`Interaction`（点击判定） |
| 数据表 | `indra_beacon`（id / world / x / y / z / effects / color / rotate_speed / owner / expire_time / active） |
| 环境可行性 | ✅ **已验证**：`ItemDisplay`、`BlockDisplay`、`Interaction`、`Display` 在 Paper 26.3 全部存在 |

**为什么用 Display 而非原版信标**
- 完全可控外观（任意物品模型、任意大小、可做浮空/装饰造型）
- 不受原版信标方块的位置/基座限制
- 效果与外观参数可自由配置，不局限于原版那几种

**核心功能**

| 功能 | 实现方式 |
|---|---|
| **完全模仿原版外观** | `BlockDisplay` 拼出信标底座 + 玻璃柱 + 顶部宝石，比例与半透明贴图对齐原版 |
| **自定义颜色** | 玻璃层用染色物品模型或 `BlockDisplay` 的 `BlockData` 染色，支持 16 色或任意 RGB（资源包） |
| **转动速度** | 顶部宝石用 `ItemDisplay`，通过 `setInterpolationDuration()` + 周期性 `setTransformationMatrix()`（JOML 旋转矩阵）实现匀速自转，速度以「度/秒」为单位配置 |
| **光柱** | `BlockDisplay` 纵向拉伸 或 粒子效果（`MinecraftEffect` 模块） |
| **点击激活** | 叠加 `Interaction` 实体（Display 本身不可点击），命中后触发效果 |
| **原版效果** | 速度 / 急迫 / 抗性提升 / 跳跃提升 / 力量 / 生命恢复（与原版信标一致） |
| **效果分级** | 按信标等级（1–4 级）决定效果强度，模仿原版基座层数机制 |
| **范围生效** | `radius` 半径内玩家获得增益，离开范围自动失效 |

**可配置项（`beacon.yml`）**
```yaml
beacon:
  # 外观
  glass-color: "#00BFFF"      # 支持十六进制，或原版 16 色名
  rotate-speed: 60            # 度/秒，0 = 不旋转
  rotate-axis: "Y"            # Y / X / Z / 组合
  beam-visible: true
  scale: 1.0                  # 整体缩放
  
  # 效果
  effects:
    - type: SPEED
      level: 1
    - type: HASTE
      level: 1
  effect-duration: 120        # tick，到期需重新点击
  radius: 16
  apply-to: "ALL"             # ALL / OWNER / TEAM
```

**实现要点（已验证可行）**
- Display 实体本身不可点击，**必须叠加 `Interaction` 实体**做命中判定
- Display 需 `setPersistent(true)`，否则区块卸载后丢失
- 需按世界分片维护实体引用，区块加载时重建（避免重复生成）
- 原版信标的光柱是特殊渲染，Display 方案用「半透明染色 BlockDisplay 纵向拉伸」近似，**观感接近但非像素级一致**；若要完全一致需客户端资源包配合
- 转动用 `setInterpolationDuration(N)` 设定插值时长，配合 `setTeleportDuration()` 实现平滑旋转，避免顿挫

#### B3.1 ★ 后处理效果（`/posteffect`）实测结论

> 针对「Paper 26.3 是否有支持后处理效果的方法」的专项核查，2026-09-20。

**结论：Paper 26.3 没有服务端后处理效果 API。** 已通过三种方式交叉验证：

| 核查方式 | 结果 |
|---|---|
| 全 jar 搜 `PostEffect` / `PostProcess` / `Shader` | ❌ 只命中 `MapPostProcessing`（**地图**的后期处理，与画面无关） |
| Paper 官方 Wiki | 原话：**"Post effects exist on the client (in resource packs), not the server"** |
| 协议层结构 | 后处理效果（Post Effects）是**资源包内定义的客户端渲染**，服务端只能下发「要启用哪几个」 |

**但「下发」这条路是通的** —— 通过 **PacketEvents** 可以做到：

| 项 | 内容 |
|---|---|
| 封包类 | `WrapperPlayServerPostEffects` / `WrapperCommonServerPostEffects` |
| 读写方法 | `getPostEffects()` / `setPostEffects(List<ResourceLocation>)` |
| PacketType | `PacketType.Play.Server.POST_EFFECTS` |
| 版本枚举 | `ClientVersion.V_26_3`（PacketEvents 已支持 26.3） |
| ⚠️ 关键限制 | **单向封包** —— 只能「我们发」，`list` 只能列出自己发过的，**读不到玩家当前实际生效的后处理** |

**原版内置 5 个后处理效果**（可直接下发，无需资源包）：

| ID | 效果 |
|---|---|
| `minecraft:blur` | 模糊 |
| `minecraft:creeper` | 苦力怕视角（绿闪） |
| `minecraft:entity_outline` | 实体描边（发光） |
| `minecraft:invert` | 颜色反转 |
| `minecraft:spider` | 蜘蛛视角（红八分屏） |

**因此 `/posteffect` 的可行设计**：

```
/posteffect add <玩家> <效果ID>      # 下发封包，启用效果
/posteffect remove <玩家> <效果ID>   # 重新下发不含该效果的列表
/posteffect clear <玩家>             # 下发空列表
/posteffect list [玩家]              # 只能列出「我们发过的」（受限，见上）
```

| 事实 | 说明 |
|---|---|
| 需要 PacketEvents | ✅ Indra 已是软依赖策略（见第五节），缺失则本功能自动关闭 |
| 需要资源包吗 | ❌ 原版 5 个效果不需要；**要自定义效果（如 TAB 栏渐变）才需要资源包** |
| 与 A6 TAB 栏的关系 | A6 的着色器**必须走资源包**，本封包只能启用「已存在于资源包中的效果」 |
| 生命周期 | 效果随玩家会话，重连即失效，需在 `PlayerJoinEvent` 重放（如需持久化） |

> ⚠️ **对本项目 A6/B3 的影响**：原计划「用着色器自定义 TAB 栏」依赖资源包，
> 而后处理效果是**全屏**的，**无法只在 TAB 区域生效**。
> TAB 栏的视觉自定义应改走「**资源包 + 负数字符贴图（glyph）+ 字体宽度欺骗**」路线，
> 后处理效果（`/posteffect`）作为**独立的画面氛围功能**（受伤红屏、洞穴冷色等）单列。
> 建议把 `/posteffect` 提升为独立功能项 **A8**，见下。

- 演奏时它会把快捷栏替换成音符图标（`cacheQuickBar` 缓存 → `restoreQuickBar` 还原）
- 若需深度定制（和弦、乐谱系统、多乐器切换），需自行重写

**可配置项（从字节码确认）**
- `sound`：音符音色（默认 `BLOCK_NOTE_BLOCK_PLING`）
- `pitch`：音高映射
- `material`：快捷栏音符图标所用材质

> 也就是说，虽然无源码，但**音色与外观有配置空间**，只有逻辑（按键映射、演奏模式）不可改。

**集成价值**：适合作为服务器娱乐玩法，配合主菜单做入口。

### 5.2 PacketEvents 统一策略（已按你的要求确定）

**问题**：三个插件各自内置 PacketEvents，会形成多重初始化冲突。

| 插件 | 依赖方式 | 是否内置 PacketEvents |
|---|---|---|
| MessageBridge | 无声明 | ✅ 内置（编译进 jar） |
| LoadingScreenSkipper | 无声明 | ✅ 内置（编译进 jar） |
| ImagePreviewer | **`depend: [packetevents]`** | ❌ 外部依赖（正规做法） |

> ℹ️ PacketEvents 本身**已支持 26.3**（`ClientVersion.V_26_3` 存在），
> 且已封装了 A8 所需的后处理效果封包，无版本风险。

**策略：以 ImagePreviewer 的做法为基准**

```
Indra  →  softdepend: [packetevents]      # 软依赖外部独立插件
       →  compileOnly packetevents-spigot  # 只编译期引用，不打包
```

**具体动作**

| 步骤 | 说明 |
|---|---|
| 1 | 服务端单独安装 **PacketEvents** 插件（官方版） |
| 2 | Indra 在 `plugin.yml` 声明 `softdepend: [packetevents]` |
| 3 | Gradle 用 `compileOnly` 引用，**不 shade 进 jar** |
| 4 | 运行时检测 PacketEvents 是否存在，**不存在则降级**（关闭 TAB / 消息路由 / 图片功能，其余功能正常） |
| 5 | 对 MessageBridge / LSS：**接受其内部内置**（无源码无法改），但确保 Indra 不与之抢注入 —— 三方共存需实机测试 |

**降级方案（PacketEvents 缺失时）**

| 功能 | 降级行为 |
|---|---|
| A6 TAB 栏 | 退回 Scoreboard Team 方案（视觉简化，功能保留） |
| **A8 后处理效果** | **本模块整体禁用**（无封包则无任何下发通道） |
| B2 消息路由 | 关闭前缀转换，保留原生消息 |
| B4 图片预览 | 功能不可用（该插件本身就强依赖） |
| C3 LSS | 功能不可用（该插件本身就强依赖） |
| **其余全部功能** | **不受影响**（A1–A5、A7、B1、C1 都不依赖封包） |

> ⚠️ **收益**：Indra 本体不再捆绑 PacketEvents，避免版本锁定与冲突，且缺失时能优雅降级。
